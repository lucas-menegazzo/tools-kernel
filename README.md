# tools-kernel

This is an internal-tools factory for a regulated fintech. It replaces a Power Apps estate with PostgreSQL-backed apps that share audit, RLS, approval and PII-masking primitives.

**Architecture, indexed:** [DeepWiki](https://app.devin.ai/org/lucas-menegazzo-demo/wiki/lucas-menegazzo/tools-kernel?branch=master)
> Generated by Devin from the repository. Nobody drew it.

## What it replaces

The legacy Power Apps are in `legacy/`, unpacked from their `.msapp` files. See [`legacy/README.md`](legacy/README.md) for what each one does wrong.

## How to run it end to end

```bash
git clone https://github.com/lucas-menegazzo/tools-kernel.git
cd tools-kernel
docker-compose up -d
```

The init script in the container loads the kernel and the apps wired into `docker/init-db.sh`. To load or reload any app by hand:

```bash
docker exec tools-kernel-postgres psql -U tools_kernel -d tools_kernel -f /apps/<app>/schema.sql
docker exec tools-kernel-postgres psql -U tools_kernel -d tools_kernel -f /apps/<app>/seed-data.sql
```

Run the checks:

```bash
npm run check
```

Start the dev server:

```bash
npm start
```

Open `http://localhost:3001`.

## How to sign in as different people

The actor selector in the UI sets the PostgreSQL session context. Pick one of the seeded actors and the queue changes.

- **marina.alves@thefintechcompany.com.br** — `Analista Compliance`, Team A. Sees only her KYC cases. Cannot approve.
- **helena.castro@thefintechcompany.com.br** — `Supervisor Compliance`, Team A. Sees all Team A cases. Can approve.
- **juliana.prado@thefintechcompany.com.br** — `Gerente Compliance`, Management. Sees all cases.

The same mechanism applies to the other apps: the database resolves `current_actor_id()`, `current_actor_team()` and `has_role(...)` for every query.

## How to add a new app

Create a directory under `apps/<app-name>/` with:

- `app.yaml` — entities, fields, PII flags, deadlines with basis, RLS policies, business rules and UI requirements
- `schema.sql` — tables, indexes, RLS, triggers, soft-delete and approval-band wiring
- `seed-data.sql` — synthetic data with the right teams and roles

Then load it with the `psql` commands above. Add it to `docker/init-db.sh` if it should be part of the default `docker-compose up` setup.

## What is deliberately not implemented

- **Identity and auth** — actors are mocked in the UI; the database only sees `current_actor_id()`, `current_actor_roles()` and `current_actor_team()`.
- **Customer data** — CPFs and names are deliberately invalid or synthetic. No real customer records are used.
- **Bureau connectors** — external identity, credit and sanctions checks are not wired in.
- **Remaining apps** — only the apps in `apps/` are built. The rest of the legacy estate is left as-is.
